# Week 3 — Monte Carlo simulation: the `ising` sampler

A Rust CLI that samples the two-dimensional Ising model on an L×L periodic
lattice (J = 1) along an ascending temperature ramp, with the two update
rules of the course: single-spin Metropolis flips and Wolff cluster flips.
Everything the week grades is recomputed from the raw rows the tool writes;
this README regenerates every committed file from a clean clone.

The CLI contract is [`ising.design.toml`](ising.design.toml); it matches the
instructor's reference copy `week3-ising.design.toml` section for section
(`diff` is empty).

Reproducibility: the random stream comes from an in-crate xoshiro256++
generator seeded by `--seed`, so the same command gives the same
`series.jsonl` on any machine (checked below).

## Install

From `week3/`:

```bash
cargo install --path . --quiet   # builds in release mode, puts ising on PATH
```

The analysis scripts need Python 3 with `numpy` and `matplotlib`; the script
tests use `pytest`. Everything below runs from `week3/`.

## Runs

`runs/` and `artifacts/` are git-ignored (about 350 MB together); every
folder is regenerated by the commands below, in this order.

```bash
# Part 1 VERIFY: two temperatures and the Boltzmann ratio
ising --update metropolis --l 64 --t-from 1.8 --t-to 1.8 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2026 --out runs/T1.8
ising --update metropolis --l 64 --t-from 3.0 --t-to 3.0 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2026 --out runs/T3.0
ising --update metropolis --l 64 --t-from 3.1 --t-to 3.1 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2026 --out runs/T3.1

# Part 1 VERIFY: one seed, one run
ising --update metropolis --l 64 --t-from 1.8 --t-to 1.8 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2026 --out runs/a
ising --update metropolis --l 64 --t-from 1.8 --t-to 1.8 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2026 --out runs/b
diff runs/a/series.jsonl runs/b/series.jsonl && echo IDENTICAL
ising --update metropolis --l 64 --t-from 1.8 --t-to 1.8 --t-step 0.1 \
  --discard 2000 --measure 2000 --seed 2027 --out runs/c

# Part 1 VERIFY: the ramp recording (spins.jsonl is committed)
ising --update metropolis --l 64 --t-from 1.5 --t-to 3.5 --t-step 0.05 \
  --discard 2000 --measure 200 --every 20 --seed 2026 --out runs/ramp
cp runs/ramp/spins.jsonl spins.jsonl

# Part 2: two sizes, coarse and critical-window grids (about a minute)
ising --update metropolis --l 32 --t-from 1.5 --t-to 3.5 --t-step 0.1 \
  --discard 2000 --measure 5000 --seed 1042 --out artifacts/coarse-l32
ising --update metropolis --l 64 --t-from 1.5 --t-to 3.5 --t-step 0.1 \
  --discard 2000 --measure 5000 --seed 42 --out artifacts/coarse-l64
ising --update metropolis --l 32 --t-from 2.0 --t-to 2.6 --t-step 0.05 \
  --discard 2000 --measure 100000 --seed 1042 --out artifacts/window-l32
ising --update metropolis --l 64 --t-from 2.0 --t-to 2.6 --t-step 0.05 \
  --discard 2000 --measure 100000 --seed 42 --out artifacts/window-l64

# Part 4: the same critical window with cluster flips (about 95 s)
ising --update wolff --l 64 --t-from 2.0 --t-to 2.6 --t-step 0.05 \
  --discard 20000 --measure 100000 --seed 42 --out artifacts/wolff-l64
ising --update wolff --l 32 --t-from 2.0 --t-to 2.6 --t-step 0.05 \
  --discard 20000 --measure 100000 --seed 1042 --out artifacts/wolff-l32
```

## What the week found

- Part 1: T = 1.8 gives mean |M| = 0.9569 with 4.1 % accepted (Onsager
  0.9568); T = 3.0 gives 0.0412 with 46.1 % accepted; the T = 3.0/3.1 energy
  histogram log ratio follows the Boltzmann slope; the same seed reproduces
  `series.jsonl` byte for byte.
- Part 2: mean |M| = 0.9865 / 0.9867 at the lowest temperature (gate: ≥ 0.9);
  susceptibility peaks at 2.3526 (L=32) and 2.3050 (L=64); the two-size
  extrapolation gives **T_c = 2.2574**, −0.52 % from Onsager's 2.26919
  (gate: within 2 %).
- Part 3: at T = 2.3 the 50-block error is 31.5× the naive one and
  τ_int = 742.6 sweeps; the binning curve has no plateau, and the bootstrap
  sd of T_c does not settle across block lengths 2000/4000/8000
  (0.0107/0.0150/0.0140), so the sampling error of the Part 2 estimate is
  **unresolved**, not 0.01.
- Part 4: the samplers agree at T = 2.3 (Equation 18: d = 0.82 ≤ 3), but the
  metropolis error is still block-length sensitive, so the agreement is
  **provisional**; the wolff peaks give **T_c = 2.2748** (+0.25 %); at T = 2.3
  one independent |m| sample costs τ_work = 1.07 sweeps of spin updates with
  clusters against 742.6 with single flips — 696× less work.

Limits worth stating to the instructor: the bootstrap error excludes
finite-size bias and the bias of fitting five grid points with a parabola
(a peak is not a parabola); two sizes cancel the leading 1/L shift but
cannot test the scaling assumption itself; and the metropolis window runs
are too short to resolve their own error bar at T_c.

## Extension (Part 3): how long is long enough

From `evidence/errors.txt` at L = 64, T = 2.3: τ_int = 742.55 sweeps, so the
100000 recorded sweeps hold n_eff = 100000/(2×742.55) ≈ **67** independent
samples. Making the correlation-corrected error as small as today's naive
error (0.000656), holding τ fixed, needs 2τ × 100000 ≈ **1.49×10⁸ sweeps**.
The measured sweep rate of this tool at L = 64 (release build, series
writing on) is 102000 sweeps / 2.90 s ≈ **3.5×10⁴ sweeps/s**, so that run
would take ≈ 4.2×10³ s ≈ **1.2 hours** — the cluster sampler of Part 4
removes the need instead, at about 10 sweeps-equivalents of spin updates per
independent sample near T_c.
